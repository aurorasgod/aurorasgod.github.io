## 先把问题写清楚

读机器人论文时，我希望先能回答三个问题：机器人看到了什么，任务如何表达，以及模型最终输出什么。

把输入和输出放在一张表里，往往比直接进入网络结构更容易理解全文。

| 内容 | 阅读时需要记录的问题 |
| --- | --- |
| 视觉输入 | 单帧、多视角还是历史图像序列？ |
| 语言输入 | 指令怎样进入模型，是否影响动作生成？ |
| 动作输出 | 关节控制、末端位姿还是离散动作 token？ |
| 训练数据 | 数据来源、机器人类型与任务范围是什么？ |

## 一个便于阅读的表示

可以先把策略抽象成：

$$
\pi_\theta(a_t\mid o_t,\ell)
$$

其中 $o_t$ 表示观测，$\ell$ 表示任务语言，$a_t$ 表示动作。这个写法用于整理问题，具体模型可能还包含历史状态、多个相机或一段动作序列。

**重点是追踪语言信息如何影响动作，以及视觉信息在何处被压缩和利用。**

### 从符号回到代码

读实现时，我会按输入、表示、输出逐步记录张量形状。下面是一段示意代码：

```python
# 示例：结构与张量维度需要对照具体论文和实现
images = batch["images"]
instruction = batch["instruction"]

visual_features = vision_encoder(images)
task_features = text_encoder(instruction)
actions = policy(visual_features, task_features)
```

如果某一步的输入与输出还说不清楚，就先把它记为待确认的问题。

## 实验应该回答什么

对比结果之前，先看实验条件：

1. 训练和测试任务是否重叠？
2. 机器人形态与动作空间是否一致？
3. 基线是否使用了相近的数据与训练预算？
4. 失败案例集中在哪些环节？

阅读笔记中可以把**论文给出的证据**与**自己的推测**分开记录，避免把一个漂亮的演示直接当成完整结论。

## 留给下一次阅读的问题

- 当前方法最依赖哪一部分数据？
- 在新环境下，视觉变化和任务变化分别会造成什么影响？
- 哪个实验可以帮助确认自己的理解？

这些问题也可以链接到下一篇相关笔记，逐步形成一组互相连接的阅读记录。

# Laplace Blog Publisher

Obsidian 桌面插件，将一篇选中的笔记转换成独立发布稿，发布到现有 Astro / GitHub Pages 博客。原笔记和原附件不修改。

## 使用

研究主页点击 **发布文章**，或在命令面板搜索 **Laplace Blog Publisher: 打开博客发布**。

1. **选择笔记**，或 **新建博客草稿**。
2. 填写标题、摘要、英文文章地址、分类、标签与日期。正文是独立发布稿，可自由编辑。
3. 点击 **预览文章与附件**，查看转换后的正文及所有待公开附件。
4. 处理未公开内部链接。可以手动改成公开网址，也可以勾选“未公开笔记的链接转为纯文字”。嵌入另一篇笔记不会自动展开。
5. 勾选公开确认，点击 **发布到 GitHub**。
6. 点击 **检查部署**，确认 GitHub Actions 成功，再点击 **打开博客**。

发布分为：检查仓库 → 导出正文与附件 → 本地构建 → 提交 → 推送。只有选中文章及其直接引用的附件进入本次提交。推送失败时保留本地提交，使用 **重试推送**。构建失败会恢复本次写入，原有文件不会被覆盖。

发布记录按来源笔记保存。修改已发布文章时保留地址，填写修订日期后重新预览、发布。原笔记移动时，同一库中的发布记录会随路径更新。两个库使用同一博客仓库，各自保留独立的发布稿和发布记录。

## 设置

- 博客仓库目录：GitHub 本地克隆的根目录。
- Git 路径：macOS 通常是 `/usr/bin/git`，沿用现有 Git 凭据配置，不保存令牌。
- Node.js 路径：用于本地构建，当前项目使用 Node.js 24。
- 默认分类：具身智能、电力电子或个人经历。

需要在博客仓库安装项目依赖。源仓库必须使用 `main`，`origin` 为 `aurorasgod/aurorasgod.github.io`。存在未提交、已暂存、未推送或落后远程的其他更改时，先在 GitHub Desktop 处理。插件不会强制覆盖远程，不会自动提交其他文件。

## 支持与边界

支持标准 Markdown、公式、代码块、普通内部链接，以及直接引用的 PNG/JPEG/WebP/GIF/SVG/PDF/MP4/MP3/WAV 附件（每个不超过 20 MB）。附件按内容摘要命名，放在 `public/images/posts/文章地址/`。删除已不用的历史附件需自行确认后处理，插件不主动删除既有资料。

Obsidian 预览用于检查发布稿、公式和附件；网站在提交前执行完整静态构建。Dataview、插件专属代码块、嵌入笔记和依赖本地环境的 HTML 需要改写成标准 Markdown。

发布日期、修订日期、分类、搜索、RSS 与热力图由网站现有代码自动处理。插件推送只更新 GitHub Pages；另一个 `chatgpt.site` 网址由 Sites 单独发布。

## 安装与源码

将本目录的 `manifest.json`、`main.js`、`core.cjs`、`styles.css` 放入仓库的 `.obsidian/plugins/laplace-blog-publisher/`，然后启用第三方插件。`data.json` 存放本机设置和发布稿，不应加入博客公开仓库。

自动验证：在网站根目录运行 `node --test tests/publisher.test.cjs`。测试使用临时本地 Git 仓库与本地 remote，不发布示例文章到线上。
